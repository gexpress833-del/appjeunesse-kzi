============================================================
3. MEMBER ≠ USER
============================================================

Le système doit distinguer :

MEMBER
= personne dans la communauté

USER
= compte permettant de se connecter

Relation cible :

MEMBER 1 ───── 0..1 USER

Un membre doit donc pouvoir exister sans compte de connexion.

C’est obligatoire pour les enfants ECODIM.

============================================================
4. MEMBER
============================================================

Le membre contient notamment :

id
first_name
last_name
birth_date
gender
photo_url
status
created_at
updated_at

La date de naissance est la source de vérité.

Ne stocke pas l’âge calculé de façon permanente sauf besoin réel.

============================================================
5. USER
============================================================

Le compte utilisateur contient notamment :

id
member_id
email
phone
password_hash
status
last_login_at
created_at
updated_at

Le USER reste optionnel pour certains membres.

15. SÉPARATION ÉGLISE / JEUNESSE
============================================================

Cette règle existe déjà et doit être CONSERVÉE.

Un responsable Église ne peut pas saisir une présence Jeunesse uniquement parce qu’un département porte le même nom.

Pour saisir une présence Jeunesse, il faut notamment :

- affectation Jeunesse active ;
- périmètre autorisé ;
- permission correspondante ;
- événement Jeunesse.

Le serveur doit refuser :

- URL manipulée ;
- POST manipulé ;
- API directe ;
- changement d’identifiant ;
- tentative de contournement frontend.

16. DOUBLE RESPONSABILITÉ
============================================================

La nomination Jeunesse ne doit pas modifier ou supprimer le département Église.
